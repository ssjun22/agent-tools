# clarify 방법 — 수렴 인터뷰

clarify는 메인이 사용자와 라이브로 진행한다(서브에이전트는 화면에 질문이 닿지 않음). 목표는 explore·plan이 의지할 *확정된 이해*를 brief로 만드는 것. 질문 수는 목표가 아니다 — ① 동결 후 수정 불가능한 brief가 **잘못된 문제·침묵 파손·설익은 이월**을 품지 않게 하는 것이 목표다.

## 산출물 모델 — transcript(원문) / brief(종료 시 1회)
인터뷰 중 영속되는 정본은 **transcript뿐**이다. Q/A 원문을 `core.sh interview-log`로 append(요약·삭제 금지 — 뉘앙스=결정, 채점의 무상태 재파생 담보). brief는 인터뷰 **종료 시 1회 생성**한다(수렴 중 증분 작성 아님). 확인된 결정도 인터뷰 중엔 별도 brief가 아니라 transcript에 `[refined]`로 남는다.
- **출처 태그** — 확정 항목엔 `[from-code]`(explorer 조사) / `[from-user]`(사람 판단) + `[R번호]`(transcript 라운드)를 붙인다. 나중에 재검증(from-code)·재협상(from-user) 경로와 원문 역링크가 된다. 미해결 큐의 `[코드]/[사용자]`와는 축이 다르다: 그건 "누가 답하나", 이건 "어디서 왔나".

## 두 모드 — 채점 루프 / ad-hoc
- **채점 루프**(기본) — 외부 격리 채점기가 매 라운드 약한 축을 지목해 다음 질문을 조준한다. 아래 「채점 루프」·「종료 체인」.
- **ad-hoc**(채점 off) — 채점기를 끈 clarify. 골격(제시형 화법·transcript·brief 1회 생성·restate·승인)은 공유하고 **다음 질문 조준·종료 판정만 메인 재량**이다. 진입: 요청이 이미 3부를 채움(fast-path) 또는 사용자 스킵 선언. 3라운드 안에 미해결 큐가 소진되면 채점이 발동조차 않으므로 초소형은 자동으로 ad-hoc이 된다.

## 화법 — 제시형
빈 질문을 던지지 않는다. **권장안을 동반**해 제시하고, 사용자의 반응으로 숨은 의도를 발견한다. 발화는 `AskUserQuestion` 다지선다(자유 텍스트로 묻지 않음, header 12자 이내, 첫 옵션이 권장이면 라벨에 `(권장)`). 예외 하나: 요청의 동기가 불명하고 가설도 서지 않을 때, 동기를 묻는 열린 질문 1개는 허용. 매듭 확인 뷰 형식은 `gate-views.md` 접점 1.

## 순서 (양 모드 공통)
0. **컨텍스트 문서 참조** — `docs/`·ADR 등 기존 문서를 먼저 읽어 중복 질문을 피한다.
1. **문제 환원** — 요청이 해법 형태면("X를 추가해줘") 그것이 풀려는 문제를 재진술해 확인. 자명하면 재진술만 하고 질문은 생략.
2. **축별 채움** — 3부 각 축을 채운다. 원료는 explore가 공급하고 사용자는 고른다:
   - 성공(G-): 완료 시 관측 가능한 동작으로 재진술해 확인. 테스트 수준·대상 합의 포함.
   - 보존(C-): explorer의 `## 변경 영향 범위`를 후보 목록으로 전환, "이 중 깨지면 안 되는 것"을 multiselect로 고르게 한다. 기존 동작과 접점이 없는 신규 작업이면 그 사실을 확인하고 greenfield 채점으로 전환(보존 축 제외).
   - 비목표(N-): 인접 확장 2~3개를 제시해 "이번엔 안 한다" 경계를 확인받는다.
   - 전제(A-): 사용자의 단정("그 API는 안 씀")은 근거를 물어 A-로 승격, 근거 없으면 Q-로.

## 채점 루프 (매 라운드 · 채점 모드)
1. 답변을 받으면 transcript에 Q/A를 append(`core.sh interview-log`)하고 `core.sh score`를 실행한다. **단 3라운드까지는 채점하지 않는다**(조기 채점은 정보 없음 + 낭비).
2. 스냅샷(stdout)의 약한 축과 이유를 겨냥해 다음 질문 하나를 만든다. `SNAPSHOT_UNAVAILABLE`이면 채점 없이 축별 채움(기본 전략)으로 진행 — 채점기 장애가 인터뷰를 멈추지 않게.
3. 채점 축은 기본 4개: **문제 · 성공(G-) · 보존(C-) · 비목표(N-)**. 전제 A-·미해결 Q-는 채점하지 않고 기록만. 판별 기준은 `scripts/prompts/rubric.md`. **축 구성** — 기존 동작과 접점이 없는 신규 작업으로 확인되면(근거를 transcript에 남긴다) `score --greenfield`로 보존 축을 축 집합에서 제외한다: 없는 축을 억지로 채우거나 만점 처리하는 게 아니라 채점 대상 자체를 바꾼다. 축 구성이 직전 채점과 다르면 streak는 래퍼가 리셋.
4. 답변이 결정·제약·제외를 담으면 구조화해 사용자 확인 후 transcript에 `[refined]`(+출처 태그)로 기록한다. 답변을 한 줄로 압축하지 않는다.

## 종료 체인 (채점 모드)
```
floor(전 축 최저선) + 2연속 streak
  → Acceptance Guard (core.sh guard) — 발견 2 병렬 → closer 종합 → 코드 판정
       ① 발견자 2 독립 병렬 — contrarian(틀린 것 공격: 가정·문제·접근 반증) ·
          gap_hunter(빠진 것 탐색: 요구·제약·엣지·검증불가), 각 gap에 severity
       ② closer 종합 — [발견 결과 + transcript]를 받아 모순 조정 +
          "실행 바꿀 미결정 있나" 판정 + 발견자가 놓친 것 보완
       ③ core.sh 코드 규칙 — closer NOT_OK 또는 HIGH gap ≥1 → BLOCK · 그 외 → PASS
       BLOCK → gap을 Q-로(라우팅: [코드]→explorer / [사용자]→질문) · streak 리셋 · 라운드 되돌림
  → restate (한 문장 목표 재진술 → 사용자 승인)
  → brief 1회 생성(templates/brief.md 6섹션 + 출처 태그)
  → brief-check (core.sh brief-check — 전사 대조) → ① 착수 게이트
```
- **트리거** — guard는 floor 통과가 트리거다(그 전엔 안 돎: 발산 검토는 비싸고, 덜 명확한 transcript에선 gap이 과다해 신호가 안 됨).
- **배치** — guard를 restate **앞**에 둔다. 사용자가 구멍 난 요약을 승인하는 일이 없게. guard는 종료 확정이 아니라 "floor 통과를 기각할 마지막 기회"다.
- **판정 귀속** — 발견·종합 *의견*은 격리 lane(claude -p)이 내되, 최종 통과/차단 *규칙*은 core.sh(코드)가 소유(자가 판정 아님 — 격리 채점기와 같은 층위). severity 정의·프롬프트·집계는 `core.sh guard`와 guard 프롬프트(`scripts/prompts/guard-*.md`)가 원천 — 여기 재서술하지 않는다.
- **UNAVAILABLE** — lane 장애 시 guard 없이 "약한 점 남을 수 있음" 고지 후 사용자 승인으로(장애가 인터뷰를 멈추지 않게).
- **brief-check (전사 대조)** — brief 생성 직후 `core.sh brief-check`. 기계 태그 검사(확정 항목 `- G/C/N/A-n`의 출처 태그·R 범위) + 대조 lane(누락·왜곡·무단추가·재등장 — 근거는 transcript뿐). 사용자가 승인한 것은 매듭과 restate이지 brief 전문이 아니므로, 전사가 합의를 배반하지 않았는지 동결 전에 잡는 관문이다. FAIL이면 brief를 고쳐 재실행 — transcript에 근거가 없는 항목은 삭제하거나 Q-로 강등(사용자 확인 대상). UNAVAILABLE이면 ① 착수 뷰에 고지. **양 모드 공통**(ad-hoc 포함).
- **ad-hoc 종료** — floor·guard 없이 **메인이 미해결 큐 소진을 확인 → restate → 승인 → brief 1회 → brief-check**.

## floor 강제력
floor 미달이면 **에이전트는 닫는 질문 금지**(약한 축을 계속 판다). 단 사용자가 "충분" 선언하면 "약한 축 남음: `<축>`" 고지 후 restate+승인으로 종료 가능 — 최종 방어선은 ① 착수 게이트다. 이런 미완 종료는 lock 스냅샷에 `mode: override`로 남고 ① 뷰에 경고로 고지된다(기록+고지 — 차단 아님). floor는 에이전트 규율이고 사용자 승인이 최종이다. `자가 판정 금지`(SKILL.md)는 verify retry 루프를 겨눈 것이지 clarify 종료 판단을 겨눈 게 아니다 — 종료는 원래도 "메인이 큐 소진 확인 → 사용자 승인"이 최종이며, 채점기는 그 판단을 강화하는 외부 도구다.

## 규칙
- **One question at a time** — 한 번에 하나. 다지선다 우선.
- **혼합 질문 분리** — 사실 확인([코드])과 의향 확인([사용자])이 섞인 질문은 쪼갠다: 사실은 explore로, 의향은 사실 회수 후 제시형으로. 통째 [코드] 처리 금지.
- explorer의 `[신규 의문]` 회신은 Q- 큐에 의무 편입.
- **결정 기록 단일화** — clarify에서 확인된 결정은 transcript `[refined]`로만 남긴다. journal `문답` 이중기록은 하지 않는다(journal `문답`은 transcript가 없는 ③ 검수 전용).

## 미해결 3태그
- `[코드]` — 코드를 보면 답이 나옴 → explore가 사실로 전환. **사용자에게 묻지 않는다.**
- `[사용자]` — 사람만 답할 수 있음.
- `[이월]` — 이번에 답하지 않고 다음 사이클로. **자격**: 답이 달라져도 이번 G-·C-·N-·걸음 구조가 그대로일 때만. 경로를 바꿀 질문은 동결 전에 흡수한다.

## 비목표 / 부적합 감지
- 해법 설계 금지(그건 plan). 코드로 답할 질문을 사용자에게 묻지 않기.
- variant 공존(A/B)·탐색측정(spike·벤치마크·데이터 분석)·git 영구화가 부자연스러운 신호면 부적합을 지적하고 취소/다른 흐름을 제안한다.
