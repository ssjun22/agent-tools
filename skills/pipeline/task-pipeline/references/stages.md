# 단계 — 사이클 운영 절차

메인 세션이 지휘자다(코드 안 만짐, 사용자 창구·게이트·blocked 중계). 골격은 **기준 → [변경⇄검증] → 기록**이며, 나머지 단계는 과제의 불확실성이 정당화하는 만큼만 존재한다.

```
[수렴: clarify ⇄ explore]  … 교대, 종료 = 사용자의 brief 확인
   ↓                          (기준 설계에서 번역 막히면 반송 ↰)
[기준 설계] → [plan] → [① 착수 게이트: 통째로 동결 + 브랜치 생성]
   ↓  ← 컨텍스트 리셋: 이후 정본은 디스크
[변경 ⇄ 검증 루프]  … blocked·LIMIT → 사람 개입 이벤트 (③ 수정 판정 시 반송 ↰)
   ↓
[refactor (선택)] → [③ 검수 게이트] → [기록·종료]
```

## 게이트 어휘 (사람 판정 2개)
- **① 착수** — "이 이해와 경로에 자원을 걸어도 되는가". 어휘: `lock`(동결) / 수정(해당 단계 반송) / 중단. 동결 = brief·plan·verify cmd·상한·검수 체크리스트·선택 단계 구성을 통째로. 확인은 여러 번, 동결은 한 번.
- **③ 검수** — 기준이 아니라 **의도 부합**을 사람이 판정 + 잔여 의도 발견. 어휘: 수용 / 수정(합의 범위 내 미달 → 루프 반송) / 수용+이월(합의 밖 발견 → 다음 사이클 씨앗).
- **이벤트**(게이트 아님, 예외 경로): `blocked`(작업자 선언) · `LIMIT`(래퍼 자동, 상한 소진) → 사람 호출.

## 단계별 계약 (role · 종료 · 비목표)

| 단계 | role | 종료 | 비목표 |
|---|---|---|---|
| clarify | 숨은 의도 발굴 + 모호함 구체화(제시형 화법) | 문제 진술 + 3부 의도 진술 + 미해결 큐 소진(이월 자격) | 해법 설계 · 코드로 답할 질문을 사용자에게 |
| explore | 완성 그림 ↔ 코드 현실 중개 | 계획을 틀리지 않게 쓸 확인된 사실 | 개선점 발굴(이월) · 백과사전 조사 |
| (수렴) | 위 둘은 한 수렴의 두 수 — 교대(보통 탐색 선행) | 양쪽 충족 + 사용자 brief 확인 | 진짜 병렬 아님 |
| 기준 설계 | 성공 요소를 verify·검수로 배분 + 게으른 경로 검사 + 실패 먼저 보기 | 배분 완료 + 실패 목격(or "이미 충족") | 달성 방법 언급 · 막힌 번역 임의 봉합(clarify 반송이 정답) |
| plan | 분해 + 완료 조건 + 의존 그래프 | 이탈이 드러나는 걸음 목록 | 코드 작성 · 기준 재협상 |
| 루프 | 걸음 하나씩: 증거 정하고 → 작업 → 확인 → 커밋 | 최종 검증 PASS (or LIMIT/blocked) | plan 조용한 이탈 · 안 만진 코드 정리(이월) · 동결 수정 |
| refactor(선택) | 사이클 diff 횡단 정리 — 동작 불변 | 정리 + 최종 검증 재확인 (or skip) | 기능 추가 · 동작 변경 |
| ③ 검수 | 의도 부합을 사람이 판정 + 잔여 의도 발견 | 수용/수정/수용+이월 | 새 요구의 이번 반영(이월) |
| 기록·종료 | 재구성 가능한 마감(`core.sh close`) | 상태 파일·저널·로그 무결 | 회고·교훈 추출(학습계 몫) |

기준 설계·plan 방법은 `plan-rules.md`, clarify 방법은 `clarify-method.md`.

## 루프 상세
- 걸음마다: 판정 수단 확보(실패 먼저 보기) → 작업 → `core.sh verify <dir> --step S-n`(걸음 확인, 라운드 무카운트) → `core.sh commit <dir> S-n`. `check` 없는(human_check 전용) 걸음은 걸음 확인을 생략한다 — 판정은 ③ 검수 체크리스트로.
- 웨이브 경계에서 `core.sh verify <dir>`(최종 검증, FAIL 시 라운드 소모). 상한 도달 시 `LIMIT`.
- generator는 걸음당 1인스턴스(신선한 컨텍스트). 종료 전 발견을 `core.sh log … --tag 발견`으로 저널에 남겨 다음 generator가 상속.
- 판정은 명령이(자가 판정 금지) · 방법은 재량 · 동결 합의는 불가침.

## crew · 위임 · 병렬
- 편성: `explorer`(대량 스캔 보조) · `planner`(기준 설계+plan) · `generator`(걸음당 1) · `refactorer`(선택). 자동 의도 판정(judge)은 이월 — 필요가 입증되면 신설.
- 위임 판별식: 입력이 경로 · 출력이 파일·커밋·토큰 · 중간에 사용자 불필요 — 셋 다 예면 위임. 핵심 조사·수렴 대화는 메인 직접.
- crew 3철칙: 인계는 경로로(요약 금지) · 저널 상속(generator는 발견을 저널에) · 판정 불변(generator도 `core.sh verify` 경유, BLOCKED는 토큰 반환).
- 병렬: **이월** — core.sh에 워크트리 커맨드가 없어 같은 웨이브도 순차 실행한다. 웨이브(= `depends_on` 파생)와 `files` 서로소는 병렬화 후보 표시이며, 웨이브 경계 = 통합 최종 검증(불변식 복원 지점)은 유지.

## 컨텍스트 리셋 · resume
- ① 동결 직후 수렴·설계 대화 컨텍스트를 폐기하고 동결 문서(brief·plan·state.json)만 정본으로 루프에 진입한다. 걸음 경계에서 걸음 사이 정리(시행착오는 저널로).
- resume: `core.sh status`로 활성 사이클(final==null)을 찾아 state.json + journal을 읽고 재개. 작업 트리 불확실 시 `core.sh verify` 1회.
