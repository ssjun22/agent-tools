# Session Handoff

handoff는 간호사의 교대 인수인계다. 차트(파일, git, 결과물)는 남으니 낭독하지 말고, 교대와 함께 사라질 지식 — 이 세션이 대가를 치르고 얻은 것 — 만 넘겨라. 상황이 어떻든, 적을지 말지는 이 기준 하나로 정한다: 이 세션이 끝나면 사라지는 정보인가.

## 생성 절차

1. `scripts/new_handoff.sh <작업명>` 실행 — 새 뼈대를 `.claude/handoffs/{YYYY-MM-DD-HHMM}.md`에 `status: active`로 생성한다. 활성 여부는 파일명이 아니라 frontmatter의 `status` 필드로 관리하며, 여러 handoff가 동시에 active일 수 있다. 생성은 다른 활성본을 건드리지 않는다 — 각 handoff의 status 정리는 그 handoff를 다루는 세션의 책임이다(아래 소비 규약 참조).
2. 아래 작성 기준대로 뼈대를 채운다.
3. 가벼운 인터뷰: 아래 해당 항목이 있으면 한 번에 하나씩, 짧게 묻는다. 답이 문서를 바꾸는 질문만 하고, 대화에 이미 답이 있는 것은 묻지 않는다. 사용자가 넘기면 즉시 멈추고 해당 항목은 그대로 이월한다. 순서는 의존 방향대로:
   - 다음 액션 1번이 도출이 아니라 선택(갈래)인 경우 — 어느 갈래부터 이어갈지
   - 지금 답받으면 결정으로 승격되는 열린 질문 — 작성 시점은 사용자에게 물을 수 있는 가장 싼 순간이다
   - 사용자 확답으로 [확인] 승격 가능한 [추론]
   답은 해당 섹션에 반영한다 (확답은 [확인 — 사용자 확답]으로).
4. 저장 전 검증을 통과시킨 뒤, 저장 위치(생성된 `{YYYY-MM-DD-HHMM}.md` 경로)와 새 세션용 시작 프롬프트 한 줄을 사용자에게 알린다.

## 섹션별 작성 기준

**목표** — 있었던 만큼만 적는다. 단일이면 한 문장 + 완료 기준 ("X 실행 시 Y"), 여러 갈래면 갈래별로, 없었으면 "방향 미정"이 정직한 상태다. 없던 목표를 사후에 창작하지 말 것. 완료 기준을 대화에서 한 번도 정하지 않았다면 지어내지 말고 열린 질문에 "완료 기준 미정"으로 남긴다 — 인터뷰가 가장 싼 순간에 물어 결정으로 승격시킨다.

**현재 상황** — 상태 주장은 전부 이 섹션에만 적는다. 다른 섹션에 끼어들면 여기로 옮겨 라벨을 받는다.
- 위치: 어디까지 왔고, 진행 중이던 것이 정확히 어디서 끊기는지
- 대가를 치른 지식: 작동하는 것과 그 이유(다음 세션이 통념으로 갈아엎지 않도록) / 막힌 길과 그 이유("안 됨"만은 명령이지 지식이 아니다. 에러 메시지는 원문 그대로, 긴 스택트레이스는 결정적 프레임만. 없으면 "없음" — 부재와 누락은 다르다)
- 결정·사용자 지시와 근거: 결과물에는 "왜"가 안 남는다. 사용자가 말로 준 제약·선호·작업 방식 지시("커밋은 직접 하겠다", "이 표현 금지")는 정확한 표현으로

**다음 액션** — 1번은 재개 지점: 추가 질문 없이 실행 가능한 첫 작업. 추가 항목은 목표·현재 상황에서 도출 불가능한 것만 적는다 — 세션이 발견한 순서 의존성, 사용자가 지정한 순서, 명시적으로 합의된 목록. [추론]에 기대는 항목은 조건부로 쓴다("X 확인되면 → Y"). 나머지는 목표와 현재 상황이 이미 담고 있다.

**열린 질문** — 사용자 확인 필요 사항. 없으면 "없음".

**누락** — 작성 세션은 건드리지 않고 비워둔다. 이 문서로 작업을 이어가는 세션이 채우는 칸이다.

## 라벨 (정확성 장치)

현재 상황의 모든 진술에 붙인다:
- [확인] — 이 세션에서 실행·관찰로 검증됨 (금방 낡는 정보는 시각 병기 가능)
- [확인 — 사용자 확답] — 인터뷰에서 사용자 확답으로 검증됨 (출처가 관찰이 아니라 사용자임을 구분)
- [추론] — 증거에서 도출했으나 미검증

기억뿐이면 [추론]으로 강등하거나 빼라. 라벨 없는 추측이 문서를 거치면 다음 세션에서 사실로 신분 세탁된다. 작성 중 새로 떠오른 추측은 적지 않는다 — 검증 비용을 치른 결론만 넘긴다.

## 저장 전 검증

- 과거 서사("논의했고", "아까", "위에서") 제거 — 인수인계는 회고가 아니다
- 상대 표현("그 파일", "아까 그 문서") → 절대경로·URL·정확한 명령으로. 세션이 찾아낸 참조는 원문 그대로 남긴다
- 밀도 > 길이: 결정적 한 줄이 무해한 스무 줄에 묻히면 없는 것과 같다
- 콜드 리더 테스트: 원 대화를 못 본 세션이 이것만 읽고 첫 액션 실행 가능한가

## 소비 규약 (읽는 세션)

인수받은 간호사는 전임자를 믿되 핵심 바이탈은 자기 손으로 다시 잰다. 사용자가 특정 handoff를 지목해 요청하므로, 활성본을 선제적으로 훑거나 목록을 물을 필요는 없다 — 지목된 handoff를 이어받는다. 지목이 파일명이 아니라 작업명이면 `scripts/status.sh`(또는 `.claude/handoffs/`에서 name·`status: active` grep)로 경로만 특정한다:
1. [확인] 중 핵심 1~2개를 재확인해 실제와 대조. 불일치는 작업 전 보고
2. [추론]을 사실로 승격하지 않는다
3. 막힌 길은 기록된 이유가 여전히 유효한지만 확인 (맹목 복종도 전면 재검증도 금지)
4. 다음 액션 1번부터 시작. 문서 재요약 금지
5. handoff에 없어서 재발굴한 정보는 발견 즉시 이 문서의 누락 섹션에 한 줄씩 기록 — 다음 작성 기준의 개선 재료다
6. status는 이 handoff를 다루는 세션이 처리한다. 이어받은 작업을 마치거나 이 handoff를 폐기·대체하기로 하면 `scripts/set_status.sh <파일|스탬프> archived`로 자기 handoff의 status를 정리한다 — 활성으로 남기면 다음 세션이 계속 이어받을 대상으로 본다
