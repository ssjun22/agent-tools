# Gemini 3 Review Criteria

Gemini 3 모델의 고유 동작에 기반한 리뷰 기준. Gemini 3을 타겟으로 작성된 에이전트 시스템 프롬프트에만 적용한다.

---

## 1. Temperature 1.0 유지

temperature를 1.0 이외로 설정하고 있지 않은가.

**왜 문제인가:**
Google은 모든 Gemini 3 모델에서 temperature 1.0을 강력히 권장한다. 낮추면 루핑, 성능 저하, 예기치 않은 동작이 발생하며, 특히 복잡한 수학/추론 태스크에서 영향이 크다. 이는 "낮은 temperature = 더 결정적"이라는 다른 모델의 통념과 반대된다. 결정성이 필요한 경우 temperature 대신 thinking_level 파라미터로 제어한다.

**감지 기준:**
- temperature가 1.0 미만으로 명시적 설정되어 있는가
- "temperature를 낮춰서 일관성을 높인다" 류의 지시가 있는가
- 결정성 확보를 위해 temperature를 조정하고 있는가 (thinking_level로 대체해야 함)

**개선 예시:**
- before: `temperature=0.3`으로 설정하여 일관된 출력을 유도
- after: `temperature=1.0` 유지. 결정성이 필요하면 `thinking_level`을 조정하고, 출력 일관성이 필요하면 프롬프트의 지시와 예시를 강화

## 2. 기본 출력 간결성

상세한 응답이 필요한데 이를 명시적으로 요청하지 않고 있는가.

**왜 문제인가:**
Gemini 3은 기본적으로 간결하고 직접적인 답변을 생성한다. 다른 모델처럼 장황한 응답을 기대하면 의도보다 짧은 출력을 받게 된다.

**감지 기준:**
- 상세한 설명, 단계별 풀이, 대화체 응답이 필요한 태스크인데 출력 길이/상세도에 대한 지시가 없는가
- "자세히 설명한다", "단계별로 풀이한다" 등 명시적 상세도 지시가 빠져 있는가

**개선 예시:**
- before: "분석 결과를 보고한다"
- after: "분석 결과를 보고한다. 각 항목에 대해 근거와 함께 2-3문장으로 설명한다"

## 3. 광범위 부정문 금지

구체적 범위 없이 광범위하게 부정하는 지시가 있는가.

**왜 문제인가:**
Gemini 3은 부정문을 과잉 해석한다. "추론하지 마"라는 지시가 텍스트에서 명시된 숫자의 기본 산술 연산까지 거부하게 만든다. 다른 모델보다 부정문의 영향 범위가 훨씬 넓다.

**감지 기준:**
- "추론하지 마", "가정하지 마", "판단하지 마" 등 동사만 부정하고 범위가 한정되지 않은 지시가 있는가
- "~하지 마" 형태의 지시가 의도한 것보다 넓은 행동을 억제할 수 있는가

**개선 예시:**
- before: "외부 정보를 추론하지 마"
- after: "제공된 텍스트에 기반해서만 계산한다. 텍스트에 명시되지 않은 외부 지식은 도입하지 않는다"

## 4. 페르소나 과잉 준수

페르소나 정의가 다른 지시를 무시할 만큼 강하게 작성되어 있지 않은가.

**왜 문제인가:**
Gemini 3은 페르소나 준수가 매우 강하다. 페르소나 정의에 모호한 행동 지침이 포함되면, 이후의 구체적 지시보다 페르소나를 우선하여 다른 지시를 무시할 수 있다.

**감지 기준:**
- 페르소나 정의에 광범위한 행동 지침이 포함되어 있는가 (예: "항상 친절하게 응대한다" → 비판적 분석이 필요한 상황에서도 친절함을 우선)
- 페르소나 설명이 이후 지시사항과 충돌할 여지가 있는가
- 페르소나에 금지 행동이 구체적으로 명시되어 있는가

**개선 예시:**
- before: "당신은 친절한 도우미입니다. 항상 긍정적으로 응답합니다"
- after: "당신은 기술 문서 리뷰어입니다. 정확성을 최우선으로 한다. 오류가 있으면 명확히 지적한다"

## 5. Thinking Level 적정성

태스크 복잡도에 맞는 thinking level이 설정되어 있는가.

**왜 문제인가:**
Gemini 3의 thinking level(minimal/low/medium/high)은 추론 깊이와 비용/지연에 직접 영향을 준다. 단순 태스크에 high를 사용하면 불필요한 비용과 지연이 발생하고, 복잡한 태스크에 low를 사용하면 추론 품질이 저하된다.

**감지 기준:**
- 단순 작업(정보 추출, 분류)에 high thinking level이 설정되어 있는가
- 복잡한 작업(수학, 코딩, 다단계 추론)에 low/minimal thinking level이 설정되어 있는가
- thinking level에 대한 설정이나 언급이 전혀 없는 경우, 태스크 복잡도에 따라 권장 level을 제안한다

**개선 예시:**
- before: 모든 에이전트에 `thinking_level: "high"` 일괄 적용
- after: 정보 추출 에이전트는 `thinking_level: "low"`, 코드 분석 에이전트는 `thinking_level: "high"`

## 6. Thought Signature 필수

함수 호출(function calling)을 사용하는 에이전트에서 thought signature 처리가 누락되어 있지 않은가.

**왜 문제인가:**
Gemini 3에서 함수 호출 시 thought signature가 누락되면 400 에러가 발생한다. 텍스트/채팅에서는 에러는 나지 않지만 추론 품질이 저하된다. 이는 Gemini 3 고유의 요구사항이다.

**감지 기준:**
- 함수 호출을 사용하는 에이전트인데 thought signature 관련 설정이 없는가
- 멀티턴 대화에서 thought signature의 컨텍스트 유지에 대한 고려가 없는가
- 함수 호출을 사용하지 않는 에이전트의 경우 이 항목은 N/A로 처리한다

**개선 예시:**
- before: 함수 호출 설정에 thought signature 관련 언급 없음
- after: thought signature를 활성화하고, 멀티턴에서 signature가 유지되도록 설정

## 7. First-match 조기종료

여러 정보원을 처리해야 하는데 종합 지시가 빠져 있지 않은가.

**왜 문제인가:**
Gemini 3은 여러 정보원에서 관련 정보를 찾을 때 첫 번째 매칭에서 멈추는 경향이 있다. 명시적으로 "모든 관련 정보를 종합하라"는 지시가 없으면 불완전한 답변을 생성한다.

**감지 기준:**
- 여러 문서/소스를 분석해야 하는 태스크인데 "모든 소스를 검토", "종합적으로 분석" 등의 지시가 없는가
- 긴 문서에서 특정 정보를 추출하는 태스크에서 "첫 번째 결과만이 아닌 모든 해당 항목"을 요구하는 지시가 없는가
- 단일 소스만 처리하는 에이전트의 경우 이 항목은 N/A로 처리한다

**개선 예시:**
- before: "문서에서 관련 정보를 찾아 답변한다"
- after: "문서 전체를 검토하여 관련 정보를 모두 수집한 뒤 종합하여 답변한다. 첫 번째 발견에서 멈추지 않는다"

## 8. Split-step 검증

불확실한 기능이나 정보에 대해 검증 없이 바로 실행하도록 지시하고 있지 않은가.

**왜 문제인가:**
Gemini 3에서 불확실한 기능이나 정보를 바로 사용하면 환각이나 에러가 발생한다. 먼저 해당 기능/정보의 가용성을 확인한 후 실행하는 2단계 접근이 필요하다.

**감지 기준:**
- 외부 API, 파일 시스템, 데이터베이스 등 가용성이 불확실한 리소스에 접근할 때 사전 확인 단계가 없는가
- "~가 있으면 사용하고, 없으면 대안을 실행한다" 형태의 조건부 실행이 아닌 무조건적 실행을 지시하는가

**개선 예시:**
- before: "데이터베이스에서 사용자 정보를 조회하여 응답한다"
- after: "1) 데이터베이스 연결 가능 여부를 확인한다 2) 연결 가능하면 사용자 정보를 조회한다 3) 연결 불가하면 사용자에게 알린다"

## 9. 간결한 프롬프트 선호

추론 모델인 Gemini 3에게 불필요하게 복잡한 프롬프팅 기법을 적용하고 있지 않은가.

**왜 문제인가:**
Gemini 3은 추론 모델이므로 기존 모델용 복잡한 프롬프팅 기법(정교한 chain-of-thought 유도, 과도한 단계 분해 등)을 적용하면 오히려 과잉 분석하여 성능이 저하된다. 직접적이고 간결한 지시가 더 효과적이다.

**감지 기준:**
- 프롬프트 내에 명시적 chain-of-thought 유도("단계별로 생각해보자")가 포함되어 있는가 (thinking level로 대체 가능)
- 단순한 태스크에 불필요하게 많은 중간 단계를 강제하고 있는가
- 동일한 지시를 다른 표현으로 반복하고 있는가

**개선 예시:**
- before: "먼저 문제를 이해하고, 그다음 단계별로 분석하고, 각 단계에서 근거를 제시하며, 최종 결론을 도출하라"
- after: "문제를 분석하고 결론을 도출한다" + `thinking_level: "high"` 설정

## 10. 내장 도구와 Function Calling 동시 사용 불가

Google Search, Code Execution 등 내장 도구와 커스텀 function calling을 동시에 사용하도록 설정하고 있지 않은가.

**왜 문제인가:**
Gemini 3은 내장 도구(Google Search, URL Context, Code Execution)와 커스텀 function calling을 동시에 사용할 수 없다. 이를 무시하면 API 에러가 발생한다.

**감지 기준:**
- 에이전트 설정에 내장 도구와 커스텀 함수가 동시에 정의되어 있는가
- 프롬프트에서 내장 도구와 커스텀 함수를 함께 사용하도록 지시하는가
- 도구를 사용하지 않는 에이전트의 경우 이 항목은 N/A로 처리한다

**개선 예시:**
- before: Google Search + 커스텀 API 호출 함수를 동시에 tools에 등록
- after: 내장 도구가 필요한 단계와 커스텀 함수가 필요한 단계를 별도 에이전트로 분리하거나, 하나의 도구 유형만 사용
