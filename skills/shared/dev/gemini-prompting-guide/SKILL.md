# Gemini 3 프롬프팅 가이드

Google Gemini 3 모델의 특성에 맞는 프롬프트를 설계하는 방법을 안내하는 스킬.
자세한 전략 설명과 예시는 `references/gemini3-strategies.md`를 참고.

## 핵심 원칙 요약

Gemini 3 프롬프트 설계 시 다음 8가지 원칙을 적용:

1. **온도 기본값 유지** — `temperature=1.0` 고수. 낮추면 추론 오류 발생 가능
2. **지연 시간 최소화** — 낮은 지연이 필요하면 thinking level `LOW` + `think silently` 지시
3. **추론과 외부 정보 구분** — `do not infer` 같은 광범위한 부정 대신 "제공된 텍스트로만 계산/추론하고, 외부 지식은 사용하지 마라"처럼 구체적으로 분리
4. **분할 단계 확인** — 불확실한 정보/기능은 먼저 존재 여부를 확인하고 STOP 조건을 명시한 뒤 본 작업 수행
5. **제약 조건은 마지막에** — 부정 제약, 형식 제약, 정량 제약은 프롬프트 끝(컨텍스트 → 기본 지시 → 제약 순서)에 배치
6. **페르소나를 구체적으로** — 모호한 페르소나는 지침을 무시하는 원인. 금지 사항까지 명확히 기술
7. **그라운딩 명시** — 가상 시나리오나 사실과 다른 컨텍스트를 다룰 때 "이 세션의 컨텍스트만이 유일한 사실"임을 선언
8. **합성 질문은 마지막에** — 대규모 문서 분석 시 질문을 문서 뒤에 배치하고 `Based on the entire document above...`로 시작

## 사용 방법

1. 사용자가 Gemini 3용 프롬프트 작성을 요청하면 이 스킬을 활성화
2. `references/gemini3-strategies.md`를 로드하여 해당 전략의 상세 내용과 예시를 참고
3. 사용자의 요청 맥락에 맞는 전략을 1개 이상 선택해 적용
4. 작성된 프롬프트에 어떤 전략을 적용했는지 간략히 설명

## 적용 체크리스트

프롬프트 작성 후 검토:
- [ ] `temperature` 설정이 필요한 경우 1.0 권장 여부 안내했는가?
- [ ] 부정 제약이 포괄적이지 않고 구체적으로 분리되어 있는가?
- [ ] 중요한 제약 조건이 프롬프트 끝에 배치되어 있는가?
- [ ] 그라운딩이 필요한 경우 명시적 선언이 포함되어 있는가?
- [ ] 대규모 문서 분석이면 질문이 컨텍스트 뒤에 배치되어 있는가?
