> **작성일**: 2026-02-06

## 📋 Understanding Summary

### 목적
슬랙 스크럼 스레드를 Obsidian 주간 보고서로 자동 변환

### 사용자
7명 팀의 스크럼마스터

### 입력/출력
- **입력**: 슬랙에서 복사한 텍스트 (3가지 패턴)
  1. **한 주 요약**: "진행 중인 주요 작업" (주로 월요일)
  2. **수요일**: "어제 한 일", "오늘 할 일"
  3. **금요일**: "어제 한 일", "오늘 할 일"
- **출력**: Markdown 문서를 `{OBSIDIAN_VAULT}/group meeting/{N}월 {W}주차.md` 형식으로 저장

### 핵심 기능
1. 한글 이름으로 팀원 자동 인식 (이준형, 윤상준, 정성광, 송윤민, 이승, 김범수, 최영준)
2. 현재 날짜 기준 자동 파일 탐지 (있으면 업데이트, 없으면 생성)
3. **메인-하위 구조로 작업 관리**:
   - 한 주 요약 → 메인 항목 (진행 중인 작업)
   - 수/금 업데이트 → 하위 항목 (상세 작업)
   - 자동 매칭 (70%+ 유사도)
   - 매칭 실패 시 "기타" 항목 하위에 추가
4. 한 주 요약: 새 문서 생성, 수/금: 기존 문서 업데이트
5. 미참여자 명시적 알림 ("수요일 최영준 내용이 없습니다")

### 제약사항
- 설정 파일로 경로 관리
- 30초 이내 처리
- 영구 보관
- 슬랙 API 연동 없음 (수동 복사-붙여넣기)

## 🏗️ Architecture

### Simple Append-First Design

```
User Input (Slack Text)
    ↓
┌─────────────────────────────────────┐
│  1. Date Context Detector           │
│     - 현재 날짜 → 주차 계산         │
│     - 파일명 생성                   │
├─────────────────────────────────────┤
│  2. File Resolver                   │
│     - 파일 존재? UPDATE : CREATE   │
├─────────────────────────────────────┤
│  3. Slack Text Parser               │
│     - 팀원 이름 추출                │
│     - 섹션 헤더 인식                │
│     - 작업 항목 추출                │
├─────────────────────────────────────┤
│  4. Document Appender               │
│     - 팀원 섹션 찾기                │
│     - 작업 항목 추가 (중복 체크 X) │
│     - 미참여자 알림 생성            │
├─────────────────────────────────────┤
│  5. File Writer                     │
│     - Obsidian 경로에 저장          │
│     - 타임스탬프 업데이트           │
└─────────────────────────────────────┘
    ↓
Output (Markdown file + Console Report)
```

## 🔧 Components

### 1. Date Context Detector
**입력**: 현재 날짜 (system date)
**출력**: `{요일, 월, 주차, 예상 파일명}`

**로직**:
```python
현재 날짜 = 2026-02-06 (금요일)
→ 월 = 2월
→ 주차 = 1주차 (2월 1일부터 7일까지)
→ 예상 파일명 = "2월 1주차.md"
→ 입력 타입 추론:
   - "진행 중인 주요 작업" 포함 → 한 주 요약 (CREATE 가능)
   - "어제 한 일" 포함 → 수/금 업데이트 (UPDATE)
```

**주차 계산**:
- 매월 1일이 속한 주 = 1주차
- `week = (day_of_month - 1) // 7 + 1`

### 2. File Resolver
**입력**: `{예상 파일명, Obsidian vault 경로}`
**출력**: `{모드, 문서 내용 or 템플릿}`

**로직**:
```
경로 = {OBSIDIAN_VAULT}/group meeting/2월 1주차.md

IF 파일 존재:
    → UPDATE 모드
    → 기존 문서 읽기
ELSE:
    → CREATE 모드
    → 템플릿 로드
```

### 3. Slack Text Parser
**입력**: 슬랙 텍스트
**출력**: 팀원별 작업 목록

**파싱 규칙**:
1. 한글 이름 패턴 매칭 (`\b[가-힣]{2,4}\b`)
2. 섹션 헤더 인식:
   - "진행 중인 주요 작업", "이번 주 목표"
   - "어제 한 일", "어제한일"
   - "오늘 할 일", "오늘 한 일"
3. 작업 항목 추출 (줄바꿈 기준)

**출력 구조**:
```python
{
    "이준형": {
        "section": "어제 한 일",
        "items": [
            "차이홍 STT API 처리 시간 조사",
            "LampSTG 오토스케일링 설정"
        ]
    },
    ...
}
```

### 4. Document Appender (Main-Sub Structure)
**입력**: `{문서, 파싱 결과, 요일}`
**출력**: 업데이트된 문서

**로직**:
```
입력 타입 판단:
IF "진행 중인 주요 작업" 섹션 포함:
    → 한 주 요약 모드 (CREATE)
    → 각 팀원 "📋 진행 중인 작업"에 메인 항목만 추가
    → 하위 항목 없음 (아직 수/금 업데이트 전)
    → 프로젝트 그룹화 적용 (2개 이상인 경우)

ELSE IF "어제 한 일" 섹션 포함:
    → 수/금 업데이트 모드 (UPDATE)
    FOR EACH 팀원 in 파싱 결과:
        1. 문서에서 해당 팀원 섹션 찾기
        2. 기존 메인 항목 파싱 (프로젝트 구조 유지)
        3. 새 작업 항목 매칭:
           FOR EACH "어제 한 일" 항목:
               - 메인 항목과 70%+ 유사도 체크
               - 매칭 성공 → 해당 메인 항목 하위에 "  - {item} (완료)" 추가
               - 매칭 실패 → "기타" 메인 항목 하위에 추가

           FOR EACH "오늘 할 일" 항목:
               - 메인 항목과 70%+ 유사도 체크
               - 매칭 성공 → 해당 메인 항목 하위에 "  - {item}" 추가 (완료 표시 없음)
               - 매칭 실패 → "기타" 메인 항목 하위에 추가

        4. "기타" 항목이 없으면 자동 생성

미참여자 체크:
    기존 팀원 목록 - 파싱된 팀원 = 미참여자
    → "📝 참고 사항"에 알림 추가
    (예: "⚠️ 수요일 최영준 내용이 없습니다.")
```

**매칭 알고리즘**:
1. 키워드 추출 (상태 단어 제거: "완료", "마무리", "배포", "수정됨")
2. 일반 단어 제거 ("기능", "작업", "개발", "구현")
3. Jaccard 유사도 계산: `intersection / union`
4. 70% 이상 → 매칭 성공

**인덴트 규칙**:
- 메인 항목: `- Azure STT 기술 조사`
- 하위 항목: `  - Azure STT API 문서 읽기 (완료)` (2 spaces)

### 5. File Writer
**입력**: 최종 문서
**출력**: 파일 저장 + 리포트

**작업**:
1. Obsidian 경로에 저장
2. "_마지막 업데이트" 타임스탬프 갱신
3. 콘솔에 리포트 출력:
   - 저장 경로
   - 업데이트된 팀원 목록
   - 미참여자 알림

## ⚠️ Error Handling

### 1. 설정 파일 없음
```
→ 사용자에게 Obsidian vault 경로 요청
→ config.yaml 자동 생성
→ 알림: "config.yaml을 생성했습니다"
```

### 2. Obsidian 폴더 없음
```
→ group meeting/ 디렉토리 자동 생성
→ 알림: "group meeting 폴더를 생성했습니다"
```

### 3. 팀원 이름 파싱 실패
```
→ 전체 텍스트를 "📝 파싱 실패 항목" 섹션에 저장
→ 알림: "⚠️ 팀원 이름을 찾을 수 없습니다. 수동으로 정리해주세요."
```

### 4. 파일 쓰기 권한 없음
```
→ 현재 디렉토리에 백업 저장
→ 알림: "권한 문제로 ./weekly-summary-backup.md에 저장했습니다"
```

### 5. 신규 팀원 발견
```
→ 문서 끝에 새 팀원 섹션 자동 추가
→ 알림: "✨ 새 팀원 '신입사원' 섹션을 추가했습니다"
```

## 🧪 Edge Cases

### Case 1: 월 경계
```
1월 마지막 주 → 2월 첫 주
→ 새 문서 생성 ("2월 1주차.md")
→ 기존 문서 보존
```

### Case 2: 일부 팀원 업데이트 누락
```
수요일에 최영준, 이승 업데이트 없음
→ 해당 팀원 섹션은 변경 없음
→ "📝 참고 사항"에 추가:
   "⚠️ 수요일 최영준 내용이 없습니다."
   "⚠️ 수요일 이승 내용이 없습니다."
```

### Case 3: 주말 실행
```
토/일요일에 실행
→ 가장 가까운 금요일 기준 주차 사용
→ 알림: "주말이므로 2월 1주차 문서를 사용합니다"
```

### Case 4: 섹션 헤더 변형
```
"오늘 한 일", "오늘할일", "오늘 한일"
→ 키워드 매칭으로 유연하게 인식
```

## 🎯 Decision Log

### Decision #1: Approach Selection
- **결정**: Smart State-Aware Parser (단일 진입점)
- **대안**: Explicit Mode Selection, Separate Skills
- **이유**: 사용자 실수 방지, 단순한 UX, 확장 용이

### Decision #2: Complexity Level
- **결정**: Main-Sub Structure with Smart Matching
- **대안**: Flat Structure (완료/진행 중 분리), Simple Append-First
- **이유**: 한 주 요약과 상세 작업의 연관성 명확화, 진행 상황 추적 용이

### Decision #3: Missing Member Notification
- **결정**: 명시적 알림 ("수요일 최영준 내용이 없습니다")
- **대안**: 조용히 스킵
- **이유**: 스크럼마스터 팔로우업 가능

### Decision #4: Configuration Management
- **결정**: YAML 설정 파일
- **대안**: 환경변수, 하드코딩
- **이유**: 유연성 + 버전 관리 + 팀원 목록 관리 용이

### Decision #5: Error Handling Philosophy
- **결정**: Partial Success (부분 저장 + 에러 리포트)
- **대안**: All-or-Nothing
- **이유**: 일부라도 저장하는 것이 나음
