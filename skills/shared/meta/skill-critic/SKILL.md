# Skill Critic

스킬 패키지를 4개 차원에서 비평하고, 개선 방안을 대화로 제시한다.
스킬 파일을 직접 수정하지 않는다 (개선은 사용자 또는 skill-creator에 위임).

> 이 스킬은 자동 트리거되지 않는다. `/skill-critic` 또는 명시적 요청으로만 실행된다.

## 비평 관점

다음 4개 차원에서 스킬을 평가한다:

1. **간결성과 분리** — SKILL.md가 간결한가, resources가 성격에 맞게 분리되어 있는가
2. **패키징과 표준** — frontmatter·폴더 구조·writing style이 표준을 따르는가
3. **역할과 경계** — 역할이 선명한가, non-goals와 HITL 체크포인트가 있는가
4. **실질적 유용성** — Claude에게 비자명한 정보를 제공하는가, 완료 조건이 검증 가능한가

각 차원의 상세 기준은 [`references/critic-dimensions.md`](references/critic-dimensions.md)를 참조한다.

## 비평 절차

### 입력 수집

비평 시작 전 확인:

1. **스킬 경로** — 비평 대상 스킬의 디렉토리 경로

경로가 제공되지 않으면 추측하지 말고 사용자에게 질문한다.
경로가 존재하지 않거나 SKILL.md가 없으면 즉시 중단하고 경로를 재확인한다.

### Step 1: 파일 수집

1. 스킬 디렉토리 트리를 요약한다 (모든 파일/폴더 경로 나열).
2. SKILL.md 전체를 읽는다 (필수).
3. 번들 리소스는 비평 판단에 충분한 수준으로 읽는다.
   - references/: 전체 구조와 주요 내용을 파악한다. 대용량 파일은 목차·섹션 제목·도입부를 확인하여 SKILL.md와의 중복·누락을 판단한다.
   - scripts/: 실행하지 않는다. 전체를 읽어 목적, 입출력, SKILL.md에서의 참조 여부를 확인한다.
   - assets/: 텍스트 파일은 내용을 확인한다. 바이너리는 파일명과 용도만 기록한다.
4. 비평 출력에서 직접 인용은 1~2문장(25단어 이내)으로 제한한다.
   위치는 파일 경로 + 섹션 제목으로 기록한다.

### Step 2: 유형 판별

SKILL.md 내용을 바탕으로 스킬 유형(워크플로우형/대화형/참조형/메타형)을 판별한다.
판별 기준과 유형별 비평 조정 규칙은 [`references/critic-dimensions.md`](references/critic-dimensions.md)의 "유형 판별과 차원 가중치 조정" 섹션을 참조한다.

### Step 3: 차원별 비평

[`references/critic-dimensions.md`](references/critic-dimensions.md)를 읽고, 판별된 유형의 가중치 조정을 적용하여 각 차원별로 비평한다.

차원당 최대 3개, 총 최대 10개 이슈를 기록한다 (중복·사소한 항목 제외).

### Step 4: 결과 출력

판별된 유형을 테이블 위에 한 줄로 명시한 뒤, 비평 결과를 아래 형식의 테이블로 출력한다 (최대 10행):

| # | 차원 | 심각도 | 위치 | 이슈 | 개선안 |
|---|------|--------|------|------|--------|

- "개선안"은 실행 가능한 변경으로 작성한다 (어떤 파일, 어떤 섹션, 무엇을 추가/제거/이동/명확화).
- HITL 체크포인트 확인은 유형별 가중치 조정에 따른다. 워크플로우형은 필수, 대화형은 암시적 허용, 참조형은 제외.
- 결과를 파일로 저장하지 않는다. 여러 라운드를 자동 반복하지 않는다.

테이블 출력 후 비평을 종료한다.
