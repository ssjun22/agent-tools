# 비평 차원 정의

## 차원 1: 실질적 유용성

- Claude에게 비자명한(non-obvious) 정보를 포함하고 있는가
  - 범용 지식으로 해결 가능한 내용만 있다면 스킬로서 가치가 낮다
- 구체적인 사용 시나리오나 예시가 있는가
  - 어떤 요청이 들어올 때 어떻게 행동해야 하는지 명확한가

## 차원 2: 정보 완전성과 분리

### 정보 완전성

- 스킬 목적 달성에 필요한 핵심 정보가 모두 포함되어 있는가
  - 프레임워크/도구의 고유 동작처럼 Claude가 기본 지식으로 알 수 없는 내용이 있는가
- 코드 예시가 있어야 이해 가능한 개념에 예시가 빠져 있지 않은가
<!-- - 제거 또는 압축된 내용이 있다면, 해당 정보가 다른 파일에 보존되어 있는가 -->

### 간결성

- SKILL.md가 핵심 절차/규칙만 담고 있는가
- 장황한 설명이나 중복이 있는가
- SKILL.md와 references 간 정보 중복이 없는가
  - 단, 동일 정보라도 **소비 주체나 용도가 다르면** 중복으로 판단하지 않는다 (예: SKILL.md의 개념 설명 vs scripts 내 생성 템플릿)
  <!-- - 상세 정보는 references에, 핵심 절차만 SKILL.md에 -->

### 파일 분리

- references/scripts/assets 각각의 성격에 맞게 분리되어 있는가
  - references/: 절차 실행에 필요한 참조 문서 (읽기용)
  - scripts/: 자동화 실행 로직 (실행용)
  - assets/: 템플릿·예제 파일 (생성물 기반)
  - 성격이 다른 내용을 혼재하거나, 불필요하게 쪼개지 않았는가
- 대용량 references에 대한 탐색 가이드(검색 패턴/키워드)가 있는가

## 차원 3: 패키징과 표준

- frontmatter(name/description)가 스킬의 목적을 정확히 전달하는가
- disable-model-invocation 여부가 스킬 성격에 적합한가
  - 자동 트리거 스킬: description이 오탐/미탐 없이 구체적인가
  - 명시적 호출 스킬: description에 불필요한 트리거 조건이 없는가
- SKILL.md에서 번들 리소스를 실제로 참조하고 있는가
- writing style이 imperative/infinitive form을 따르는가

  <!-- - 폴더 구조(SKILL.md, scripts/, references/, assets/)가 표준에 맞는가 -->

## 차원 4: 역할과 경계

- 스킬의 1차 역할이 단일하고 선명한가
- Non-goals가 명시되어 역할 경계가 닫혀 있는가
- 다른 스킬이나 일반 작업으로 위임해야 할 것을 끌어안고 있지 않은가
- 사용자 확인이 필요한 지점이 명시되어 있는가
  - 입력 부족, 불확실성, 파괴적 변경, 덮어쓰기 등

## 유형별 비평 조정

**워크플로우형** — 가장 엄격하게 비평한다.

- HITL 체크포인트가 파괴적 동작이나 외부 부수효과 앞에 있어야 한다
- 역할 경계(non-goals)가 닫혀 있어야 한다

**대화형** — 유연성을 존중한다.

- 완료 조건이 사용자 판단에 위임되어 있어도 이슈로 기록하지 않는다
- HITL은 암시적(대화 흐름 속 질문)이어도 충분하다
- 역할 경계가 열려 있는 것이 의도적 설계일 수 있으므로, non-goals 부재만으로 이슈를 제기하지 않는다

**참조형** — 검색성과 정보 밀도를 중심으로 비평한다.

- HITL 체크포인트, 완료 조건은 평가 대상에서 제외한다
- 대신 대용량 references의 탐색 가이드(검색 패턴, 목차) 유무를 중점 확인한다
- 패턴/규칙 간 중복·모순이 없는지 확인한다

**메타형** — 범용성을 우선한다.

- 개념 설명이 SKILL.md에 포함되어 있어도 절차의 전제 조건이면 이슈로 기록하지 않는다
- 역할 경계와 완료 조건은 워크플로우형보다 느슨해도 허용한다
