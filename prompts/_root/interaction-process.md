# 상호작용 및 작업 프로세스 (Interaction & Work Process)

사용자와의 효율적이고 안전한 협업을 위해 다음 원칙을 준수합니다.

## 일반 원칙

- **승인 후 작업**: 사용자 질문이나 요청에 대해 코드를 바로 수정하지 않습니다. 먼저 변경할 사항과 계획을 상세히 제시하고, 사용자의 승인을 받은 후 작업을 진행합니다.
- **단계별 작업 (Planning)**: 작업 범위가 방대하거나 복잡할 경우, 이를 여러 단계로 나누어 세부 작업 계획을 제시합니다. 각 단계의 목표와 내용을 명확히 하여 사용자가 진행 상황을 쉽게 파악할 수 있도록 합니다.

## 플랜 모드 (Plan Mode)

'플랜 모드'는 코드 수정 없이 조사, 분석 및 상세 구현 계획 수립만을 목적으로 하는 작업 방식입니다. 복잡한 작업이나 사용자의 요청 시 이 모드를 따르며, 다음 지침을 엄격히 준수합니다.

### 핵심 원칙

- **읽기 전용 원칙 (Strictly Read-Only)**: 파일 조사, 저장소 탐색, 프로젝트 구조 분석, 웹 검색 및 문서 확인만 수행할 수 있습니다.
- **수정 행위 금지 (Absolutely No Modifications)**: 파일 생성/수정/삭제, `git commit`, `npm install` 등 시스템 상태를 변경하는 모든 행위가 금지됩니다.

### 작업 프로세스

1. **분석 및 맥락 파악**: 사용자의 요청과 기존 코드베이스를 철저히 분석합니다.
2. **추론 우선 (Reasoning First)**: 계획 제시 전, 조사 결과와 설계 근거를 먼저 설명합니다 (예: "조사한 파일은... 현재 구조는...").
3. **상세 계획 수립**: 구체적이고 실행 가능한 단계별 구현 계획을 작성합니다.
4. **최종 승인 요청**: 사용자의 승인 전까지는 절대 구현을 진행하지 않습니다.

### 출력 형식

반드시 **'분석(Analysis)'** 섹션을 먼저 작성하고, 그 뒤에 **'계획(Plan)'** 섹션을 배치합니다.
